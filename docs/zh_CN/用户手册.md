# pkq 用户手册

## 1. 项目简介

pkq 是一款基于 Rust 开发的跨发行版 Linux 软件包查询工具。内置 HTTP/HTTPS 原生客户端，可实时连线官方/镜像源读取最新仓库元数据索引，全程不调用任何 Shell 子进程，不下载软件包实体文件。

面向运维工程师和系统管理员，在 RPM 和 DEB 混合环境中提供统一的包查询命令。

## 2. 全局选项

| 选项 | 说明 | 默认值 |
|------|------|--------|
| `-o, --output FORMAT` | 输出格式：human \| json | human |
| `--refresh` | 强制刷新仓库缓存 | false |
| `--offline` | 离线模式，仅用本地缓存 | false |
| `--cache-ttl SECONDS` | 缓存 TTL | 86400 (24h) |
| `--legacy-exit-code` | 兼容模式：无论结果如何均以 0 退出 | false |

## 3. 命令参考

### 3.1 info — 包详情

```bash
# 查询本地已安装包
pkq info bash

# 查询仓库最新版本
pkq info nginx --repo

# 未安装包自动 fallback 到仓库查询并提示安装命令
pkq info nginx
```

### 3.2 list — 包内文件列表

```bash
# 列出已安装包的文件
pkq list bash

# 列出仓库中包的文件
pkq list nginx --repo
```

### 3.3 owns — 文件归属包

```bash
# 查找本地哪个已安装包拥有该文件
pkq owns /bin/bash

# 在仓库中查找
pkq owns /usr/bin/htop --repo
```

### 3.4 deps — 正向依赖

```bash
# 已安装包的依赖
pkq deps bash

# 仓库中包的依赖
pkq deps nginx --repo
```

### 3.5 rdeps — 反向依赖

```bash
# 哪些已安装包依赖 bash
pkq rdeps bash

# 仓库中哪些包依赖 bash
pkq rdeps bash --repo
```

### 3.6 search — 搜索

关键词搜索包名与摘要，并按文件路径检索哪个包提供该文件。支持正则表达式。

```bash
# 关键词搜索（包名+摘要；不对描述正文做子串匹配，避免噪音）
pkq search vim

# 文件路径搜索（以 / 开头自动检测，等价 apt-file search / dnf provides）
pkq search /usr/bin/htop

# 正则表达式搜索
pkq search '^vim.*common$' --regex

# 仅搜索本地已安装
pkq search vim -i

# 搜索仓库
pkq search nginx --repo
```

搜索结果按相关性分层排序（精确/前缀/包含 > 摘要词边界 > 模糊命中）；
摘要模糊命中（如搜索 sudo 时命中 sudoku）默认折叠为单行
「可能相关」段，`--all` 展开。文件路径默认每包展示 5 条，
`--all` 展开全部。

### 3.7 rdeps — 反向依赖（补充）

反向依赖默认限流 50 条，`--all` 查看全部：

```bash
pkq rdeps bash --all
```

状态标签按精确版本判定（name+version+release+arch）：仓库中同名
不同版本的包显示 `[未安装]`。

### 3.8 source — 源码包/二进制包互查

```bash
# 自动识别输入是二进制包名还是源码包名
pkq source libpam-modules
pkq source nginx
```

输出该源码包生成的全部二进制包，并按精确版本标注 `[已安装]` /
`[未安装]`；排序规则：主同名包置顶 > 已安装优先 > 主架构 > 字母序。

### 3.9 changelog — 变更日志

```bash
pkq changelog bash
pkq changelog nginx --repo
```



### 3.10 cache — 缓存管理

```bash
pkq cache status                    # 各缓存目录占用
pkq cache update                    # 强制刷新仓库元数据
pkq cache clean [target] [--yes]    # 清理：all | index | repos | contents
```

`cache update` 逐源输出刷新进度：`✓` 在线成功、`△` 在线失败已回退
本地缓存（附原因，如 `HTTP 401（认证失败）`/`响应超时`）、`✗` 彻底失败。
**有源未刷新成功即视为失败**：输出 ⚠ 提示并返回退出码 `1`（脚本可检测）。
`cache clean` 默认需追加 `--yes` 确认。

## 4. 输出格式

### Human（默认）

纯文本 `key: value` 格式，对齐 `rpm -qi` / `dpkg -s` 风格：
```
Name        : bash
Version     : 5.2.15
Architecture: x86_64
Summary     : It is the Bourne Again Shell
```

### JSON

```bash
pkq info bash -o json
```

## 5. 网络异常处理

查询命令在网络不可用时**静默降级**使用本地缓存（不刷屏）；
`cache update` 为显式刷新操作，会逐源输出 ✓/△/✗ 进度与原因。

刷新结果语义：

| 场景 | 汇总输出 | 退出码 |
|------|---------|--------|
| 全部源在线成功 | `在线成功 N 个` | 0 |
| 部分源失败（已回退本地缓存） | ⚠ 提示失败数与原因 | 1 |
| 全部源失败（无任何缓存可用） | 刷新失败提示 | 1 |

使用 `--offline` 完全禁止网络请求（此时 `cache update` 直接拒绝）。

## 6. 退出码

| 退出码 | 含义 |
|--------|------|
| `0` | 查询命中 / 更新全部成功 |
| `1` | 未找到 / 部分未达成 |
| `2` | 错误（无效参数、网络与缓存皆不可用等） |

`--legacy-exit-code` 可回退 v0.1 的恒 0 退出行为。
