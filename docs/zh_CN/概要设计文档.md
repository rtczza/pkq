1. 文档目标
本文档为 pkq 工具提供重构后的高层架构设计。新增了原生网络 IO 模块与元数据缓存 TTL 管理机制，旨在解决本地缓存过期的致命问题，指导后续详细设计与代码开发。受众包括系统架构师与 Rust 开发工程师。

2. 阶段完成验证准则
[x] 网络 IO 方案合规：明确定义使用 Rust 原生网络库（ureq / reqwest）获取元数据，严禁调用网络类 Shell 命令子进程。

[x] 缓存策略清晰：包含基于 TTL 的本地元数据缓存与强制刷新（--refresh）机制。

[x] 跨体系实时性：RPM 与 DEB 适配器均支持实时在线获取最新 Repo 索引。

[x] 边界控制：严格限定网络请求仅用于元数据/索引读取，绝不下载软件包实体。

3. 项目背景与问题描述
在多 Linux 发行版运维与镜像构建中，本地包管理器的缓存（如 /var/cache/apt 或 /var/cache/dnf）常因用户长时间未执行 apt update / dnf makecache 而陈旧过期。
若检索工具仅读取本地磁盘缓存，会导致查不到新上线的包、版本号不匹配或依赖关系错乱等致命问题。因此，pkq 必须具备原生实时网络同步能力，在必要时自动请求官方/镜像源获取最新的 repomd.xml 或 Packages 索引，确保查询结果与线上实际仓库严格一致。

4. 产品目标与范围

4.1 产品定位
面向运维工程师和系统管理员，在 RPM 和 DEB 混合环境中提供统一的包查询工具。核心痛点：跨发行版查询命令不统一 + 本地缓存过期需要联网刷新。pkq 是只读查询工具，不安装、不卸载、不修改系统状态。

4.2 包含在范围（In-Scope）
实时网络同步：内置 HTTP/HTTPS 原生客户端，自动/按需下载并解析远程仓库元数据（RPM: repomd.xml, *.xml.gz；DEB: Packages.gz）。

智能缓存与 TTL：在用户目录（如 ~/.cache/pkq/）下维护元数据缓存，支持基于时间戳（TTL）的自动更新与 --refresh 强制刷新。

10 项核心查询功能（每项均支持本地已安装 + 线上仓库双数据源）：

| # | 子命令 | 功能说明 | 参考命令 |
|---|--------|----------|---------|
| 1 | `info <pkg> [--repo]` | 包详情（名称、版本、描述、大小、架构、许可证等） | rpm -qi / dpkg -s |
| 2 | `list <pkg> [--all] [--repo]` | 包内文件列表（按路径排序） | rpm -ql / dpkg -L |
| 3 | `owns <path> [--all] [--repo]` | 文件归属包（支持通配符，目录归属限流展示） | rpm -qf / dpkg -S |
| 4 | `deps <pkg> [--repo]` | 正向依赖关系（RPM 端能力反查为真实包名） | rpm -qR / apt-cache depends |
| 5 | `rdeps <pkg> [--all] [--installed-only] [--repo]` | 反向依赖（强依赖 + 能力集匹配，对齐 dnf repoquery --whatrequires） | rpm --whatrequires / apt-cache rdepends |
| 6 | `search <pattern> [--regex] [--all] [-i] [--repo]` | 关键词（包名+摘要）+ 文件路径双索引；词边界相关性分层 | dnf search / apt-file search |
| 7 | `source <pkg>` | 源码包/二进制包互查（精确版本标注安装状态） | dnf repoquery --source / dpkg -s Source |
| 8 | `changelog <pkg> [--repo]` | 变更日志 | rpm -q --changelog / apt changelog |
| 9 | `cache status\|update\|clean` | 缓存管理（占用统计 / 强制刷新 / 分类清理） | dnf makecache（部分） |

> v0.2.0 起统一限流参数为 `--all`（解除默认 50 条/每包 5 文件的折叠限流），
> 退出码语义为 `0` 命中 / `1` 未找到或部分未达成 / `2` 错误。

4.3 不在范围（Out-of-Scope）
- 安装/卸载/升级：pkq 是只读查询工具，不碰系统状态
- 验证 (verify)：需要逐文件校验，实现复杂且低频
- 包构建：属于开发者工具，不是运维场景
- 事务历史：属于包管理器自身事务记录
- 模块/group 管理：发行版特定概念，跨发行版不统一
- 仓库管理：属于包管理器配置操作
- 软件包实体下载：绝不上网下载 .rpm 或 .deb 安装包文件
- 子进程调用：严禁调用系统 apt、dnf、curl、wget 等子进程

5. 系统整体架构
系统架构在底层增加了 网络同步与缓存管理层 (Network & Cache Layer)，形成“本地数据库 + 在线元数据”的双驱动模式。

5.1 信任边界与数据流
数据流向：

CLI 接收命令，若涉及仓库检索（如 pkq info nginx --repo），触发 NetworkCacheManager。

NetworkCacheManager 校验 ~/.cache/pkq/ 下对应仓库索引的过期时间（TTL，默认 24h）及 HTTP Header (ETag/If-Modified-Since)。

若过期或传入 --refresh，使用 Rust 原生 HTTP 库（如 ureq）直接连接远程 Repo URL，下载最新的元数据索引压缩包存入缓存。

适配器解压并解析最新的 XML / Control 文本，构建 PkgMetadata 并渲染输出。

6. 运行环境约束
网络约束：出站 HTTP/HTTPS (80/443) 可达（若网络不可用且缓存存在，降级使用旧缓存并提示 Warning）。

Rust 版本：MSRV 1.75.0+。

依赖约束：严格禁止使用 std::process::Command。网络 IO 必须使用原生 Rust crate (ureq 或 reqwest)。

7.4 Backend Trait 完整定义（10 项接口）

```rust
pub trait PkgBackend: Send + Sync {
    fn system_type(&self) -> PackageSystem;

    /// 1. info: 包详情
    fn get_package_details(&self, name: &str, source: PackageSource, cfg: &CacheConfig) -> Result<Option<PkgMetadata>>;

    /// 2. list: 包内文件列表
    fn list_files(&self, name: &str, source: PackageSource, cfg: &CacheConfig) -> Result<Vec<String>>;

    /// 3. owns: 文件归属包
    fn find_file_owner(&self, file_path: &str, source: PackageSource, cfg: &CacheConfig) -> Result<Vec<String>>;

    /// 4. deps: 正向依赖
    fn get_dependencies(&self, name: &str, source: PackageSource, cfg: &CacheConfig) -> Result<Vec<Dependency>>;

    /// 5. rdeps: 反向依赖
    fn get_reverse_dependencies(&self, name: &str, source: PackageSource, cfg: &CacheConfig) -> Result<Vec<String>>;

    /// 6. search: 关键词搜索
    fn search_packages(&self, keyword: &str, source: PackageSource, cfg: &CacheConfig) -> Result<Vec<PkgMetadata>>;

    /// 7. find: 按文件路径搜索仓库中的包
    fn find_by_file(&self, file_path: &str, cfg: &CacheConfig) -> Result<Vec<FileSearchResult>>;

    /// 8. source: 源码包/二进制包互查
    fn get_source_package(&self, name: &str, source: PackageSource, cfg: &CacheConfig) -> Result<Option<SourcePackageInfo>>;
    fn get_binaries_from_source(&self, source_name: &str, source: PackageSource, cfg: &CacheConfig) -> Result<Vec<String>>;

    /// 9. changelog: 变更日志
    fn get_changelog(&self, name: &str, source: PackageSource, cfg: &CacheConfig) -> Result<Vec<ChangelogEntry>>;

    /// 10. provides: 按能力搜索包
    fn find_providers(&self, capability: &str, source: PackageSource, cfg: &CacheConfig) -> Result<Vec<String>>;
}
```

8. 外部依赖选型规划
允许使用的 Crate (Permitted)
ureq (v2.x)：原生 HTTP/HTTPS 客户端，用于下载仓库索引元数据。

clap / serde / serde_json / rusqlite / flate2 / quick-xml：核心依赖。

严格禁止的 Crate/行为 (Banned)
❌ std::process::Command：严禁调用系统 curl、wget、apt、dnf 子进程。

❌ 下载二进制包实体：任何发起对 .rpm 或 .deb 实体包 HTTP 请求的代码视为严重违规。

❌ comfy-table：不使用表格库，输出为纯文本 key: value 格式。

9. 风险点与限制说明
网络超时与镜像源不可用：添加合理的 HTTP 超时（默认 10 秒）与自动降级机制（若网络失败则使用本地旧缓存并提示 Warning）。

大索引文件网络开销：使用 HTTP条件请求（If-Modified-Since / ETag），避免在索引未变更时重复下载几十兆的 XML 文件。
