# pkq User Manual

## 1. Introduction

pkq is a cross-distro Linux package query tool written in Rust. It ships with a
native HTTP/HTTPS client that reads the latest repository metadata index from
official/mirror sources in real time — never spawning shell subprocesses and
never downloading package payload files.

It targets operations engineers and system administrators who need a unified
query command across RPM and DEB environments.

## 2. Global Options

| Option | Description | Default |
|--------|-------------|---------|
| `-o, --output FORMAT` | Output format: human \| json | human |
| `--refresh` | Force-refresh repository metadata cache | false |
| `--offline` | Offline mode, local cache only | false |
| `--cache-ttl SECONDS` | Cache TTL | 86400 (24h) |
| `--legacy-exit-code` | Compatibility mode: always exit 0 | false |

## 3. Command Reference

### 3.1 info — Package Details

```bash
# Query a locally installed package
pkq info bash

# Query the latest version from the repository
pkq info nginx --repo

# Uninstalled packages fall back to the repository and print the install command
pkq info nginx
```

### 3.2 list — Package File List

```bash
# List files of an installed package (path-sorted)
pkq list bash

# List files of a repository package
pkq list nginx --repo
```

### 3.3 owns — File Ownership

```bash
# Find which installed package owns a file
pkq owns /bin/bash

# Search in the repository
pkq owns /usr/bin/htop --repo
```

Supports glob patterns (`*/bin/unzip`). For shared directories, ownership lists
are truncated at 50 entries by default (`--all` to show all).

### 3.4 deps — Forward Dependencies

```bash
# Dependencies of an installed package
pkq deps bash

# Dependencies of a repository package
pkq deps nginx --repo
```

Output is grouped into `Depends / Recommends / Suggests / Conflicts / Replaces`.
On RPM, sonames and `config(...)` capabilities are resolved to real package
names with version constraints preserved (e.g. `glibc (>= 2.17)`).

### 3.5 rdeps — Reverse Dependencies

```bash
# Which installed packages depend on bash
pkq rdeps bash

# Which repository packages depend on bash
pkq rdeps bash --repo
```

Semantics are aligned with `dnf repoquery --whatrequires`: matching covers the
target package's name, explicit provides and primary binary paths, restricted
to strong dependencies (Requires). Truncated at 50 entries by default;
`--all` shows all. The bottom summary always matches the list exactly.

### 3.6 search — Search

Search packages by name/summary keyword, or find which package provides a file
by path. Regex is supported.

```bash
# Keyword search (name + summary; no substring matching over descriptions)
pkq search vim

# File-path search (a leading / switches automatically; equivalent to
# apt-file search / dnf provides)
pkq search /usr/bin/htop

# Regex search
pkq search '^vim.*common$' --regex

# Installed packages only
pkq search vim -i

# Search the repository
pkq search nginx --repo
```

Results are relevance-ranked: exact/prefix/substring name matches, then
word-boundary summary matches, then fuzzy summary matches. Fuzzy summary hits
(e.g. searching `sudo` also matching *sudoku*) are collapsed into a single-line
"Related" section; `--all` expands it. File paths show 5 entries per package
by default; `--all` expands them.

### 3.7 rdeps — Reverse Dependencies (extras)

Reverse dependencies are truncated at 50 entries by default; `--all` shows all:

```bash
pkq rdeps bash --all
```

The installed/repo status tag is determined by exact version match
(name+version+release+arch): a repository package with the same name but a
different version correctly shows `[not installed]`.

### 3.8 source — Source/Binary Package Lookup

```bash
# Input is auto-detected as a binary or source package name
pkq source libpam-modules
pkq source nginx
```

Lists all binary packages generated by the source package, tagged
`[installed]` / `[not installed]` with exact version matching. Sort order:
main same-name package first > installed first > primary arch > alphabetical.

### 3.9 changelog — Change Log

```bash
pkq changelog bash
pkq changelog nginx --repo
```

### 3.10 cache — Cache Management

```bash
pkq cache status                    # Per-directory cache usage
pkq cache update                    # Force-refresh repository metadata
pkq cache clean [target] [--yes]    # Clean: all | index | repos | contents
```

`cache update` prints per-source progress: `✓` fetched online,
`△` fetch failed but fell back to the local cache (with reason, e.g.
`HTTP 401 (authentication failed)` / `timed out`), `✗` failed outright.
**A source that could not be refreshed counts as a failure**: a ⚠ line is
printed and the exit code is `1` (script-detectable). `cache clean` requires
`--yes` unless you want the confirmation prompt.

## 4. Output Formats

### Human (default)

Plain `key: value` text aligned with the `rpm -qi` / `dpkg -s` style:

```
Name        : bash
Version     : 5.2.15
Architecture: x86_64
Summary     : It is the Bourne Again Shell
```

### JSON

```bash
pkq info bash -o json
```

## 5. Network Failure Handling

Query commands degrade **silently** to the local cache when the network is
unavailable; `cache update` is an explicit refresh and prints per-source
✓/△/✗ progress with reasons.

Refresh outcome semantics:

| Scenario | Summary output | Exit code |
|----------|---------------|-----------|
| All sources fetched online | `N sources fetched online` | 0 |
| Some sources failed (fell back to local cache) | ⚠ failure count + reasons | 1 |
| All sources failed (no cache at all) | refresh-failed notice | 1 |

Use `--offline` to disable all network access (then `cache update` refuses to
run).

## 6. Exit Codes

| Exit code | Meaning |
|-----------|---------|
| `0` | Query hit / update fully successful |
| `1` | Not found / partially unsuccessful |
| `2` | Error (invalid arguments, network and cache both unavailable, etc.) |

`--legacy-exit-code` restores the v0.1 behavior of always exiting 0.
